# 沉香品牌官网 V1.0 产品与技术设计文档（已按静态部署修订）

版本：1.0 · 2026-11-05 · 状态：可运行 MVP / 待正式上线审查

## 1. 产品目标与边界

定位：品牌展示与获客销售并重。价格策略：单商品可选择公开标价或询价。首版完成产品展示、品牌内容、文章科普、咨询提交、后台管理与商品上下架。无购物车、支付、会员、订单、物流、短信营销。

**质量口径**：代码是 MVP 初稿，含可运行基础能力，不代表生产环境验收完成。演示数据、演示图片不等于真实商品和经营信息。

## 2. 技术架构

- 品牌官网：Vue 3 + Vue Router + Vite，编译为静态文件，Nginx `/` 托管。
- 后台：Vue 3 + Element Plus + Vite，独立编译为静态文件，Nginx `/admin/` 托管。
- 后端：FastAPI + SQLAlchemy + PyMySQL。
- 数据库：MySQL 8；本地独立开发可用 SQLite。
- 图片：管理员上传 JPG/PNG/WebP，服务端校验并转换成 WebP，落到 Docker volume；Nginx `/uploads/` 静态读。
- 路由：`/api/v1/**` API；统一域名避免生产跨域。
- 部署：Docker Compose 挂载编译后的 `dist`，对外暴露端口 8080 便于接已有 HTTPS 反代。
- SEO：SPA 默认页面的 JS 数据抓取存在限制；首版配置基本 meta，生产级产品/文章详情页 SEO 列为**未完成**，需选择 HTML 预渲染/独立生成或 SSR 边缘方案。**后台上架即时生效与纯构建期 SSG 不能直接同时满足**。

## 3. 前台页面

### 3.1 首页
- 顶部 logo/导航；Hero 文案与视觉；精选商品卡；品牌生活方式引导；页脚。
- Hero 标题、副标题、图片路径通过后台“品牌资料”配置，推荐商品通过 featured 标记配置。
- 基础状态：无推荐商品时显示空白列表；接口故障时主框架仍可打开。

### 3.2 商品列表
- 按可见分类筛选，默认只查询发布状态为 `published` 的产品。
- 支持翻页，每页 12 件，商品卡展示封面/名称/摘要/公开价或询价。
- 分类隐藏≠关联商品下架，正式版可加校验规则。

### 3.3 商品详情
- 图片、摘要、来源文字、香气描述、推荐用途、库存状态、价格或询价。
- 咨询时附带产品 ID。
- 当前一个商品只有一个价格/单位；同商品多规格独立价属 V1.1（product_variants）。
- 下架产品在公共 API 不可见、直接访问返回 404；已售罄仍可以展示。

### 3.4 知识文章
- 列表与详情，发布状态控制可见性。
- 正文首版纯文本换行，刻意不开放不可信 HTML，避免 XSS。以后可增加安全富文本处理。

### 3.5 公司/联系
- 公司简介、地址、微信、邮箱、电话、WhatsApp；联系表单。
- 管理员须填写真实品牌与联系人资料后才能正式上线。

## 4. 后台功能

| 模块 | 权限 | 操作 |
|---|---|---|
| 登录 | 管理员 | 账号/密码登录，8h JWT |
| 产品 | 管理员 | 新增、编辑、删除、封面上传、上下架、推荐、价格模式、库存 |
| 分类 | 管理员 | 新增/编辑/删除（已有商品禁止删除）、显示开关、排序 |
| 文章 | 管理员 | 新增、修改、删除、草稿/发布/隐藏 |
| 品牌资料 | 管理员 | 名称、标语、首页文案、联系信息 |
| 咨询线索 | 管理员 | 查询、改为已联系/已结束 |

**业务流程 A：发布商品**  登录 → 产品管理 → 新增 → 上传照片 → 填信息/价格策略 → 状态设置 published → 保存 → 前台实时加载。

**业务流程 B：下架商品**  编辑 → hidden → 保存 → 前台列表/详情立即不可访问；历史咨询记录保留。

**业务流程 C：获客询价**  浏览产品 → 详情 → 填称呼与联系方式 → 保存 inquiries → 管理员后台跟进 → 更新状态。

**业务流程 D：品牌内容**  后台修改公司资料、首页文案 → 保存 → 前台 API 获取最新内容，无需重新打包。

## 5. 数据模型与关系

初版 6 张业务表：

| 表 | 核心字段 | 说明 |
|---|---|---|
| `admins` | id, username, password_hash, created_at | 管理员登录 |
| `categories` | id, name, slug, sort_order, visible | 商品分类 |
| `products` | id, category_id, name, slug, sku, summary, description, image, images(JSON), origin, scent, usage, price_mode, price, unit, stock_status, status, featured, sort_order, created_at, updated_at | 产品 |
| `articles` | id, title, slug, excerpt, body, cover, status, sort_order, created_at, updated_at | 文章 |
| `settings` | key, value | 网站品牌配置 |
| `inquiries` | id, name, contact, channel, message, product_id, status, created_at | 咨询记录 |

关系：categories (1)→(N) products；products (1)→(N) inquiries（可为空）。

唯一约束：`admins.username`、`categories.slug`、`products.slug`、`products.sku`、`articles.slug`。

字段约束：`products.price_mode` = fixed / inquiry；`products.status` = draft / published / hidden；`stock_status` = available / sold_out。

创建方式：后端启动时 SQLAlchemy `Base.metadata.create_all`，仅为 MVP；数据库变更建议迁移到 Alembic，MySQL 正式上线前保留版本化迁移文件。数据库建表结构的权威来源为 `backend/app/main.py` ORM 类，避免 SQL 与代码双重维护。

## 6. API 约定

公共 GET：`/api/v1/site`、`/api/v1/categories`、`/api/v1/products`（category/q/featured/page/page_size）、`/api/v1/products/{slug}`、`/api/v1/articles`、`/api/v1/articles/{slug}`。

公共 POST：`/api/v1/inquiries`，必填 name/contact，选填 product_id/message。

认证 POST：`/api/v1/admin/login` 返回 access_token，后续 `Authorization: Bearer <token>`。

管理员 GET/POST/PUT/DELETE：`/api/v1/admin/products`、`/api/v1/admin/categories`、`/api/v1/admin/articles`；设置 `GET/PUT /api/v1/admin/settings`；咨询 `GET /api/v1/admin/inquiries` 与 `PUT /api/v1/admin/inquiries/{id}`；图片 `POST /api/v1/admin/upload`。

全部 API 的交互结构以运行时 `/api/docs` 为准。

## 7. 视觉设计系统

配色：松绿 #233a2c、背景米白 #fbfaf6、古铜金 #a9773e。排版以宋体标题搭配清晰无衬线正文。前台宽度最大 1180px，移动端小于 700px 双列商品卡。后台采用 Element Plus 的信息型管理界面。图片采用原创抽象 SVG **开发占位**，需替换为已授权真实图片。

## 8. 合规和风险

- 沉香健康功效不得无依据宣称治疗/改善疾病；勿将传统使用等同临床疗效。
- 产地、树种、天然结香、奇楠、无添加等声称须有供应商证据。
- 涉及沉香跨境贸易时核对对应物种 CITES 与当地法律。
- 咨询数据涉及个人联系方式；生产前增加隐私告知、同意机制、数据保留/删除规则。
- 生产前对后台登录及匿名咨询加限速、验证码/蜜罐、审计日志；设置 HTTPS 与后台操作监控。
- JWT 密钥和数据库口令必须通过环境变量管理，禁止提交真实密钥。
